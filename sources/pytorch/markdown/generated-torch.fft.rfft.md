torch.fft.rfft[#](https://docs.pytorch.org/docs/2.15/generated/torch.fft.rfft.html#torch-fft-rfft "Link to this heading")

==========================================================================================================================

torch.fft.rfft(_input_, _n\=None_, _dim\=\-1_, _norm\=None_, _\*_, _out\=None_) → [Tensor](https://docs.pytorch.org/docs/2.15/tensors.html#torch.Tensor "torch.Tensor")
[\[source\]](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/fft/__init__.py#L355)
[#](https://docs.pytorch.org/docs/2.15/generated/torch.fft.rfft.html#torch.fft.rfft "Link to this definition")

Computes the one dimensional Fourier transform of real-valued `input`.

The FFT of a real signal is Hermitian-symmetric, `X[i] = conj(X[-i])` so the output contains only the positive frequencies below the Nyquist frequency. To compute the full output, use [`fft()`](https://docs.pytorch.org/docs/2.15/generated/torch.fft.fft.html#torch.fft.fft "torch.fft.fft")

Note

Supports torch.half on CUDA with GPU Architecture SM53 or greater. However it only supports powers of 2 signal length in every transformed dimension.

Parameters:

*   **input** ([_Tensor_](https://docs.pytorch.org/docs/2.15/tensors.html#torch.Tensor "torch.Tensor")
    ) – the real input tensor
    
*   **n** ([_int_](https://docs.python.org/3/builtins/functions.html#int "(in Python v3.15)")
    _,_ _optional_) – Signal length. If given, the input will either be zero-padded or trimmed to this length before computing the real FFT.
    
*   **dim** ([_int_](https://docs.python.org/3/builtins/functions.html#int "(in Python v3.15)")
    _,_ _optional_) – The dimension along which to take the one dimensional real FFT.
    
*   **norm** ([_str_](https://docs.python.org/3/builtins/stdtypes.html#str "(in Python v3.15)")
    _,_ _optional_) –
    
    Normalization mode. For the forward transform ([`rfft()`](https://docs.pytorch.org/docs/2.15/generated/torch.fft.rfft.html#torch.fft.rfft "torch.fft.rfft")
    ), these correspond to:
    
    *   `"forward"` - normalize by `1/n`
        
    *   `"backward"` - no normalization
        
    *   `"ortho"` - normalize by `1/sqrt(n)` (making the FFT orthonormal)
        
    
    Calling the backward transform ([`irfft()`](https://docs.pytorch.org/docs/2.15/generated/torch.fft.irfft.html#torch.fft.irfft "torch.fft.irfft")
    ) with the same normalization mode will apply an overall normalization of `1/n` between the two transforms. This is required to make [`irfft()`](https://docs.pytorch.org/docs/2.15/generated/torch.fft.irfft.html#torch.fft.irfft "torch.fft.irfft")
     the exact inverse.
    
    Default is `"backward"` (no normalization).
    

Keyword Arguments:

**out** ([_Tensor_](https://docs.pytorch.org/docs/2.15/tensors.html#torch.Tensor "torch.Tensor")
_,_ _optional_) – the output tensor.

Example

\>>> t \= torch.arange(4)
\>>> t
tensor(\[0, 1, 2, 3\])
\>>> torch.fft.rfft(t)
tensor(\[ 6.+0.j, -2.+2.j, -2.+0.j\])

Copy to clipboard

Compare against the full output from [`fft()`](https://docs.pytorch.org/docs/2.15/generated/torch.fft.fft.html#torch.fft.fft "torch.fft.fft")
:

\>>> torch.fft.fft(t)
tensor(\[ 6.+0.j, -2.+2.j, -2.+0.j, -2.-2.j\])

Copy to clipboard

Notice that the symmetric element `T[-1] == T[1].conj()` is omitted. At the Nyquist frequency `T[-2] == T[2]` is its own symmetric pair, and therefore must always be real-valued.
