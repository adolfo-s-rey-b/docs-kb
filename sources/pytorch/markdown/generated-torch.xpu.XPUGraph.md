_class_ torch.xpu.XPUGraph(_keep\_graph\=False_)[\[source\]](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/xpu/graphs.py#L53)
[#](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.XPUGraph.html#torch.xpu.XPUGraph "Link to this definition")

Wrapper around a XPU graph.

Parameters:

**keep\_graph** ([_bool_](https://docs.python.org/3/builtins/functions.html#bool "(in Python v3.15)")
_,_ _optional_) – If `keep_graph=False`, the executable command graph will be instantiated on GPU at the end of `capture_end` and the underlying modifiable command graph will be destroyed. Note that the executable command graph will not be instantiated at the end of `capture_end` in this case. Instead, it will be instantiated via an explicit call to `instantiate` or automatically on the first call to `replay` if `instantiate` was not already called. Calling `instantiate` manually before `replay` is recommended to prevent increased latency on the first call to `replay`.

Return type:

Self

capture\_begin(_pool\=None_)[\[source\]](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/xpu/graphs.py#L73)
[#](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.XPUGraph.html#torch.xpu.XPUGraph.capture_begin "Link to this definition")

Begin capturing XPU work on the current xpu stream.

Typically, you shouldn’t call `capture_begin` yourself. Use [`graph`](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.graph.html#torch.xpu.graph "torch.xpu.graph")
, which call `capture_begin` internally.

Parameters:

**pool** (_optional_) – Token (returned by [`graph_pool_handle()`](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.graph_pool_handle.html#torch.xpu.graph_pool_handle "torch.xpu.graph_pool_handle")
 or [`other_Graph_instance.pool()`](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.XPUGraph.html#torch.xpu.XPUGraph.pool "torch.xpu.XPUGraph.pool")
) that hints this graph may share memory with the indicated pool.

capture\_end()[\[source\]](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/xpu/graphs.py#L86)
[#](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.XPUGraph.html#torch.xpu.XPUGraph.capture_end "Link to this definition")

End XPU graph capture on the current stream.

After `capture_end`, `replay` may be called on this instance.

Typically, you shouldn’t call `capture_end` yourself. Use [`graph`](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.graph.html#torch.xpu.graph "torch.xpu.graph")
, which call `capture_end` internally.

Instantiate the XPU graph. Will be called by `capture_end` if `keep_graph=False`, or by `replay` if `keep_graph=True` and `instantiate` has not already been explicitly called. Does not destroy the xpu modify command graph returned by `raw_xpu_graph`.

Return an opaque token representing the id of this graph’s memory pool.

This id can optionally be passed to another graph’s `capture_begin`, which hints the other graph may share the same memory pool.

raw\_xpu\_graph\_exec()[\[source\]](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/xpu/graphs.py#L142)
[#](https://docs.pytorch.org/docs/2.15/generated/torch.xpu.XPUGraph.html#torch.xpu.XPUGraph.raw_xpu_graph_exec "Link to this definition")

Returns the underlying xpuGraphExec\_t. `instantiate` must have been called if `keep_graph` is True, or `capture_end` must have been called if `keep_graph` is False. If you call `instantiate()` after `raw_xpu_graph_exec()`, the previously returned xpuGraphExec\_t will be destroyed. It is your responsibility not to use this object after destruction.

XPU doesn’t provide APIs to manipulate this object.
